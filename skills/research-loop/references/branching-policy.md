# Branching Policy

Branch only when contract-relevant evidence supports a distinct architecture,
mechanism, or hypothesis with a credible route to success. A bounded change
that preserves the central direction is a same-node revision. Do not branch
because capacity is idle, a parent is imperfect, or an alternative is merely
conceivable.

A branch is a new node with its own worker, workspace, evidence trail, and
resource records. It may use any evidence-backed parent. Multiple branches
from one revision are allowed only when their mechanisms are distinct and the
fixed active-node cap permits them.

Checkpoint `parent_node_id`, branch rationale, source evidence, and available
revision-plan or selected-candidate refs. Record borrowed insights when used.
Batch user escalations that require the same amendment; do not treat a proposed
amendment as binding before approval.
